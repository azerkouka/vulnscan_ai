# A02:2021 - Cryptographic Failures

**Category:** Cryptographic Failures
**URL:** https://owasp.org/Top10/A02_2021-Cryptographic_Failures/

Shifted up one position, previously known as "Sensitive Data Exposure". The
focus here is on failures related to cryptography which often lead to
exposure of sensitive data.

## Common weaknesses

- Transmitting sensitive data in clear text (HTTP, SMTP, FTP).
- Using old or weak cryptographic algorithms or protocols, or weak/default
  keys, or improper key management.
- Not enforcing encryption via directives or headers (e.g. HSTS).
- Storing passwords using simple or unsalted hashes instead of a dedicated
  password-hashing function such as Argon2, bcrypt or scrypt.
- Using deprecated hash functions such as MD5 or SHA1 for password storage.
- Improper certificate and validation checks (e.g. disabling TLS
  certificate verification).
- Using initialization vectors that are predictable or reused for
  encryption modes that require uniqueness.

## How to prevent

- Classify data processed, stored, or transmitted, and identify which data
  is sensitive according to privacy laws and business needs.
- Don't store sensitive data unnecessarily; discard it as soon as possible.
- Encrypt all sensitive data at rest and in transit with up-to-date,
  strong, standard algorithms and protocols.
- Store passwords using a strong, salted, adaptive hashing function such as
  Argon2id or bcrypt with a work factor tuned for your hardware.
- Verify independently the effectiveness of the configuration and
  settings.
