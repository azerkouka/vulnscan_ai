# A10:2021 - Server-Side Request Forgery (SSRF)

**Category:** Server-Side Request Forgery
**URL:** https://owasp.org/Top10/A10_2021-Server-Side_Request_Forgery_%28SSRF%29/

SSRF flaws occur whenever a web application fetches a remote resource
without validating the user-supplied URL, allowing an attacker to coerce
the application into sending a crafted request to an unexpected
destination, even when protected by a firewall, VPN, or another type of
network access control list (ACL).

## Common weaknesses

- Fetching a URL supplied by the user (e.g. a webhook target, an "import
  from URL" feature, a PDF/image renderer) without validating or
  restricting the destination.
- Allowing requests to internal, loopback, or link-local addresses (e.g.
  `127.0.0.1`, `169.254.169.254` cloud metadata endpoints, internal
  hostnames) from a server-side fetch.
- Following redirects from an initially-validated URL to an
  attacker-controlled or internal destination without re-validating.

## How to prevent

- From the network layer: segment remote resource access functionality in
  separate networks to reduce the impact of SSRF, and enforce
  "deny by default" firewall policies.
- From the application layer: sanitize and validate all client-supplied
  input data, enforce the URL schema, port, and destination with a
  positive allow-list, and do not send raw responses to clients.
- Disable HTTP redirections, or re-validate the destination after
  following a redirect.
- Be aware of the URL consistency to avoid attacks such as DNS rebinding
  and time-of-check/time-of-use (TOCTOU) race conditions.
- Do not deploy other security-relevant services on front-end systems
  (e.g. cloud metadata endpoints), and control local traffic on these
  systems.
