# A05:2021 - Security Misconfiguration

**Category:** Security Misconfiguration
**URL:** https://owasp.org/Top10/A05_2021-Security_Misconfiguration/

The application might be vulnerable if it is missing appropriate security
hardening across any part of the application stack, or has improperly
configured permissions, unnecessary features enabled, default accounts
still active, or overly informative error messages.

## Common weaknesses

- Missing appropriate security hardening across any part of the
  application stack, or improperly configured permissions on cloud
  services.
- Unnecessary features are enabled or installed (unnecessary ports,
  services, pages, accounts, or privileges).
- Default accounts and their passwords are still enabled and unchanged.
- Error handling reveals stack traces or other overly informative error
  messages to users.
- Security headers are not set, or are not set to secure values (e.g.
  missing `Strict-Transport-Security`, `Content-Security-Policy`).
- The software is out of date or vulnerable (see A06).

## How to prevent

- A repeatable hardening process that makes it fast and easy to deploy
  another, properly locked down environment.
- A minimal platform without any unnecessary features, components,
  documentation, or samples.
- A task to review and update configurations appropriate to all security
  notes, updates, and patches as part of the patch management process.
- A segmented application architecture that provides effective separation
  between components or tenants.
- Sending security directives to clients (e.g. security headers).
- An automated process to verify the effectiveness of configurations in
  all environments.
