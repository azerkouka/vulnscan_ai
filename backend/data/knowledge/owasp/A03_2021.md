# A03:2021 - Injection

**Category:** Injection
**URL:** https://owasp.org/Top10/A03_2021-Injection/

An application is vulnerable to injection when untrusted data is sent to an
interpreter as part of a command or query, and the attacker's hostile data
tricks the interpreter into executing unintended commands or accessing data
without proper authorization. This includes SQL, NoSQL, OS command, ORM,
LDAP, and Expression Language injection.

## Common weaknesses

- User-supplied data is not validated, filtered, or sanitized by the
  application before being concatenated into a query or command string.
- Dynamic queries or non-parameterized calls without context-aware escaping
  are used directly in the interpreter.
- Hostile data is used within object-relational mapping (ORM) search
  parameters to extract additional, sensitive records.
- Hostile data is directly used or concatenated into OS commands, shell
  scripts, or similar.

## How to prevent

- Use a safe API that avoids using the interpreter entirely, or provides a
  parameterized interface, or migrate to Object Relational Mapping Tools.
- Use positive server-side input validation, with an allow-list approach.
- For any residual dynamic queries, escape special characters using the
  specific escape syntax for that interpreter.
- Use LIMIT and other SQL controls within queries to prevent mass
  disclosure of records in case of SQL injection.

## Example (vulnerable)

```python
query = f"SELECT * FROM users WHERE username = '{username}'"
cursor.execute(query)
```

## Example (fixed)

```python
query = "SELECT * FROM users WHERE username = %s"
cursor.execute(query, (username,))
```
