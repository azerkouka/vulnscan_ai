# A09:2021 - Security Logging and Monitoring Failures

**Category:** Security Logging and Monitoring Failures
**URL:** https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring_Failures/

Previously "Insufficient Logging & Monitoring". Without logging and
monitoring, breaches cannot be detected, and this category helps detect,
escalate, and respond to active breaches.

## Common weaknesses

- Auditable events, such as logins, failed logins, and high-value
  transactions, are not logged.
- Warnings and errors generate no, inadequate, or unclear log messages, or
  logs contain sensitive data such as passwords or session identifiers.
- Logs are only stored locally, are not monitored for suspicious activity,
  or alerting thresholds and escalation processes are not in place or
  effective.
- Penetration testing and scans by dynamic application security testing
  (DAST) tools do not trigger alerts.
- The application is unable to detect, escalate, or alert for active
  attacks in real time or near real time.

## How to prevent

- Ensure all login, access control, and server-side input validation
  failures can be logged with sufficient user context to identify
  suspicious or malicious accounts, without logging the credentials
  themselves.
- Ensure logs are generated in a format that log management solutions can
  easily consume, and establish effective monitoring and alerting so
  suspicious activities are detected and responded to quickly.
- Establish or adopt an incident response and recovery plan.
- Use a redaction/allow-list strategy so that sensitive fields (passwords,
  tokens, secrets) are never written to logs, even accidentally.
